# C1联合n：进入视频跟踪

仍属于 Stage 1 — Local Combat Policy。冻结的是实验基线，不表示全部验收。
默认联合26n第8轮best.pt，固定哈希、1280、FP16、conf=0.05、NMS分支。
其他S/M作为独立候选，不在本轮无记录地替换检测器。

## 目的与原理

检测逐帧回答哪里有人、是什么身份；跟踪将连续帧候选关联到同一ID。
高级跟踪用镜头运动估计、位置/运动及外观特征共同关联。
外观模型是通用分类骨干，未专门训练游戏角色ReID。
短时未检出时保留轨迹，不代表本帧真实检出；冲突时保留不确定身份。
轨迹使用原生source_present_ns，不用frame/FPS推断时间。
本步不训练；增加规则式目标选择可视化，不输出手柄动作。
只选择当前可见、已确认、关联有效的敌人轨迹，排除队友、不确定身份和预测框。
已有目标仍有效就保持ID；失效后立即按四档重新选择：高置信度大框、
高置信度小框、低置信度大框、低置信度小框。同档按置信度、面积、ID排序。
最低置信度0.05，高置信度阈值0.25，大框阈值为画面面积1%。
可用`--target-high-confidence`和`--target-large-area`调整；面积仅是大小代理。

## PyCharm操作

1. 打开 `demo_c1_joint_n_tracking.py`，解释器 `.venv-yolo/Scripts/python.exe`，
   工作目录FPS根目录。Codex已运行`--check-only`；用户Parameters留空。
2. 点击Run，完成后在控制台打印的结果目录打开七段 `跟随演示.mp4`。

默认素材 `D:\FPS_AI_Dataset\Apex_YOLO_DAY3`：

| Episode | 场景 | 检查重点 |
| --- | --- | --- |
| 43 | 只有队友 | 是否误识别为敌人并选择 |
| 47 | 敌我都有、远距离小目标 | 小目标检出和敌我区分 |
| 79 | 反复技能遮挡 | 遮挡时取消目标、重现时恢复或重选 |
| 82 | 按住开火转火 | 目标保持和失效切换，暂不学习实际开火意图 |
| 150 | 敌人一闪而过 | 短暂目标是否检出及确认 |
| 178 | 近距离大幅转动视角 | 镜头补偿、ID连续性 |
| 320 | 多敌人中小目标 | 四档排序、多人关联 |

共2957帧。部分帧参与过C1训练，因此用于功能诊断，不能作为独立泛化验收。
后续新素材可用 `--source <目录> --episodes <编号>` 显式选择完整片段。

输出 `runs/c1_tracking/<时间>/episode_000043` 等七个子目录。
左侧原始检测、右侧跟踪，原尺寸拼接3840×1080。
每段包含tracks.jsonl、summary.json、预览图，顶层run_config.json记录完整配置。
右侧绿色框为当前选择的敌人，顶部显示保持、转火、失效等原因。
tracks.jsonl的target_selection记录候选排序和选择理由，summary.json记录事件次数。

## 查看与判断

- 持续可见人物ID是否稳定，多人靠近/交叉时是否互换。
- 短遮挡后是否恢复原ID；同一个人重复出现是否频繁建立新ID。
- 敌我是否跳变；灰色不确定需要看冲突原因，不自动视为错误。
- 左侧漏检而右侧保留记忆，与左侧检出却右侧丢ID，是不同问题。
- 框松紧变化是否造成ID重建，不将大小不同等同于身份错误。
- 一人多框是否创建多个ID；先记录，不自动放宽关联门槛。

预测框默认只记录在日志/记忆栏，不绘制；要查看黄色虚线预测可显式加`--show-predictions`。
本轮advanced/threads，max_lost=0.2秒，memory=0.8秒，
stable_geometry和group_duplicates默认关闭，先建立原跟踪基线。
内部计数不等于人工确认ID-switch准确率，需要视频复核。

若同时有GPU训练，本轮只看轨迹，不解释测速数字。
绘框编码耗时不等于战斗延迟；正式性能比较须结束训练，分别记录前向、
完整检测及检测+跟踪，不相加阶段p95。

完成后发结果目录；如有问题给2–4个时间点，例如“79片段3.2秒同一人换ID”。
Codex分析日志对应帧，区分检测断点、关联、镜头补偿和身份冲突。
流程稳定后再用少量人工确认交战片段进入攻击目标选择学习。
